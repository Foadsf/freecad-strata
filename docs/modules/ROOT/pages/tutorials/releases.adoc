= Release a design
:description: Release a version under a part number and revision, use the approval step, and mark old revisions obsolete.

*Goal:* release version V2 of the bracket and shaft for manufacturing, then revise the bracket.

== Release a version

[.steps]
. Right-click the version in the graph and choose *Release V2...*, or select it and click btn:[Release] in the details card.
. Tick the documents to release. For each, check the *part number* and the *revision*.
. Optionally edit the description.
. Click btn:[Release].

image::screenshots/10_release.png[Releasing version V2,role=screenshot,width=700]

Part numbers are pre-filled from the _Id_ property of the open document (select the document in the tree to see its properties), from earlier releases of the same document, or from the document name.
The revision is the next free letter for that part number: A, then B, C, ...; I, O, Q, S, X and Z are skipped as in ASME Y14.35, and after Y comes AA.

The version's node in the graph now carries a green chip such as *BRK-100 A*.

== Require approval

Tick *Require approval before it is released*. The button becomes btn:[Submit for approval] and the revision is created as *Pending*, with an amber chip.

An approver then opens *Releases* (kbd:[Ctrl+Shift+R]), selects the row and clicks btn:[Approve] or btn:[Reject]. The approver's name is recorded.

== The release register

*Releases* lists every part number and revision with its state, document, version, who requested it and who approved it.

image::screenshots/11_releases.png[The release register,role=screenshot,width=860]

[cols="1,3"]
|===
| btn:[Approve], btn:[Reject] | for pending revisions
| btn:[Mark obsolete] | for a released revision that is no longer valid, for example after revision B replaces A
| btn:[View] | opens the released document as a read-only copy
|===

Releases are permanent: each state change is recorded separately, and the furthest state reached counts.
A rejected revision letter can be reused.
